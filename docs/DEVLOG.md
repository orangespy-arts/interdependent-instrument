# 开发日志 · Interdependent Instrument

双人动作与声音依赖规则研究原型（soundworks v5）。两名参与者各持一部手机，手机的倾斜和晃动驱动本机发声；研究者在电脑控制台切换阶段并记录实验数据。

最后更新：2026-09-26。当前状态：**初始原型的软件实现与首轮服务器联调完成，浏览器视觉检查和双手机真机验收尚未完成。** 本文记录开发进度；启动方法见 [README](../README.md)，现场验收见 [PILOT-CHECKLIST](PILOT-CHECKLIST.md)。

## 项目基础与实现范围

- 基于 `@soundworks/create` 5.1.3 脚手架，框架及插件保持 v5，实际依赖版本锁定在 `package-lock.json`。核对时脚手架 `latest` 已指向 v6，因此没有直接使用 `latest`。
- Node 最低要求 22，`.nvmrc` 指定 24；项目采用 BSD-3-Clause 许可。
- `player` 为参与者手机端，默认入口 `https://<host>:8000/`；`controller` 为研究者端，入口 `https://<host>:8000/controller`。
- 服务器注册 `platform-init`、`sync`、`checkin`（容量 2）与 `logger`，默认 HTTPS 端口 8000。
- 原始日志 `logs/`、运行数据库 `.data/`、构建产物 `.build/`、本地配置和证书已加入 Git 忽略规则。

| 模块 | 文件 | 当前实现 |
|---|---|---|
| 参数 | `src/shared/params.js` | 音阶、传感、映射、共识、调度与音量等参数集中配置，开始记录时完整写入日志 |
| 特征提取 | `src/shared/features.js` | 重力分量 → 倾斜，角速度模长 → 强度；起落不对称平滑；阈值越过后的局部峰值检测，保留峰值原始共享时间 |
| 映射 | `src/shared/mapping.js` | 纯函数 `computeVoiceParams`，各阶段读取相同特征，改变音高、密度、音色来源与共同层规则 |
| 共识 | `src/server/Consensus.js` | 仅服务器配对峰值；每个峰值最多使用一次；拒绝过期、未来、重复及乱序峰值；维护共同层保持时间 |
| 会话 | `src/server/Session.js` | 阶段切换、记录启停、同步音、角色交换；记录参数、设备状态和计划/实际阶段顺序 |
| 音频引擎 | `src/clients/player/AudioEngine.js` | 本地 Web Audio、前瞻调度、同音阶共同层；在共同层未来起点同步执行 ducking；cue 与测量 click |
| 参与者端 | `src/clients/player.js`、`src/shared/instructions.js` | 引导使用附录 4.A 原文；直接在点击中启动音频/运动授权；随后黑屏；上报设备状态，处理防锁屏与恢复 |
| 控制端 | `src/clients/controller.js`、`src/clients/controller/` | 四阶段与待机/测量模式、组别及六种规则顺序、同步音、角色交换、10 秒特征曲线、峰值、计时和设备状态 |
| 通信 | `src/server.js` | 仅为 controller 注册研究控制命令处理器；命令串行执行并回传确认；正常终止时先关闭日志 |
| 集成检查 | `scripts/smoke.mjs` | 连接实际 HTTPS 服务，用两个 Node 客户端模拟手机，验证通信、共识、记录及清理 |

个人动作先在本机送入音频引擎，再最多约 30 Hz 上报共享状态，不等待网络返回。参与者始终播放分配给自己的声部；共同层起点、cue 和录像同步音使用未来的共享时间调度。

## 阶段映射与当前参数

| 阶段 | 音高 | 节奏密度 | 音色 | 共同层 |
|---|---|---|---|---|
| 熟悉 `familiarization` | 自己的倾斜 | 自己的强度 | 固定 | 无 |
| 分工 `division` | 音高角色的倾斜 | 密度角色的强度 | 固定 | 无 |
| 调制 `modulation` | 自己的倾斜 | 自己的强度 | 对方的强度 | 无 |
| 共识 `consensus` | 自己的倾斜 | 自己的强度 | 固定 | 两人峰值对齐后出现，个人声部减弱 |
| 待机 `idle` | — | — | — | 持续声部静音 |
| 测量 `latency-test` | — | — | — | 不播放持续声部，峰值触发本机与对方 click |

分工默认声部 0 对应音高角色、声部 1 对应密度角色，可在控制台交换。熟悉阶段固定在计划顺序首位，其余三条规则可选择六种排列；该选择写入日志，所有阶段仍由研究者手动切换。每次有效阶段切换在当前共享时间之后 0.2 秒安排同一个提示音。

当前参数均为试运行初值：

- C 五声音阶 C3–C5，三角波；节奏密度 0.5–8 音/秒，低通截止 400–6000 Hz。
- 倾斜轴 `y`，范围 ±60°；角速度强度范围 0–360°/s。已核对安装的 `@ircam/devicemotion` 1.3.1，输出单位为度/秒。
- 平滑起/落系数 0.3 / 0.05；峰值阈值 0.5，不应期 0.25 秒。
- 共识窗口 0.2 秒、共同层保持 2 秒、个人声部增益降至 0.6；共同层暂用同音阶的交错琶音。
- `phaseDuration: null`：每阶段分钟数未定，引导仍保留 `【X】`。填写后，引导总体验时长使用四阶段之和，即 `phaseDuration × 4`。

## 记录与时间含义

每次开始记录生成一个**带时间和序号前缀、包含组别编号的独立 JSONL 文件**，保存在 `logs/`，不覆盖前一次记录。每行一个 JSON 对象，`t` 为本次服务器进程共享时钟的秒数。

记录类型包括 `session`、`device`、`features`、`peak`、`phase`、`cue`、`joint`、`syncBeep`、`divisionSwap`、`disconnect` 和 `session-end`。首行包含完整参数、计划顺序和开始状态，结束行包含实际阶段顺序。

- `features` 与 `peak` 的 `t` 为手机源时间，`received` 为服务器接收时间。
- `features` 按每台手机每秒 25 个时间桶取样，每桶最多一条；实际频率受传感与网络输入影响，不保证每秒恰好 25 条。
- cue、录像同步音与共同层开始事件的 `t` 为计划播放时间，`scheduledAt` 为安排时间；它们不是麦克风实测的发声时间。
- 跨服务器重启的时间不能直接比较，需依据各组会话与录像重新对齐。

录像操作顺序：先开启录像 → 开始记录 → 起始同步音 → 各阶段体验 → 结束同步音 → 停止记录 → 待机。停止记录会等待刚安排的同步音播放时段结束；首尾声音是否实际被录像收录，以及 ±1 帧对齐精度，仍需现场确认。
