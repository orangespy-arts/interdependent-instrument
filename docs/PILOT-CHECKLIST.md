# 真机验收与试运行

这是尚未执行的硬件验收表，不表示已测得结果。每次记录设备型号、系统、浏览器、音量、网络、参数版本与日期。

## M0–M2：连接、传感和个人声音

- [ ] 同一 Wi-Fi 的两部手机经 HTTPS 加入，得到唯一编号 0 / 1；控制台不占编号。
- [ ] 两部手机在点击开始前显示附录原文；授权后只显示黑屏。
- [ ] 逐台验证倾斜方向、取值范围和晃动强度；两台的朝向/响应一致。
- [ ] 单人倾斜改变音高，晃动改变密度；静止仍有最低密度，不依赖另一人发声。
- [ ] 控制台有两条真实数据轨迹；每次峰值可见、无明显重复。

## M3–M5：依赖规则

- [ ] 分工默认 A 控音高、B 控密度，两台响应；交换后角色对应正确。
- [ ] 调制中自己保持个人音高/密度，对方晃动改变本机亮度；变化听得清。
- [ ] 共识仅在两人的峰值接近时出现共同层，单人动作不触发共同层。
- [ ] 两台共同层同起；共同层进入时个人声部减弱，退出时恢复。
- [ ] 离开共识、设备断开或不再就绪时，共同层停止，不保留旧峰值证据。
- [ ] 四阶段切换的提示音完全相同，手机屏幕没有阶段/规则信息。

## M6：持续运行与恢复

- [ ] 连续黑屏至少 10 分钟，不自动锁屏；控制台 Wake Lock 状态一致。
- [ ] 误触、长按、双击不打开控件，不滚动、不退出黑屏。
- [ ] 切后台时静音；返回前台重新申请防锁屏，恢复传感数据与声音。
- [ ] 断网/重启服务器时停止本机声音；研究者重载后可重新加入，并记录编号是否变化。
- [ ] 关闭通知声音，确认两位参与者都听得清两台手机。

## M7：记录与录像

- [ ] 首尾各播放一次同步音，录像与日志都有对应事件。
- [ ] 文件含参数、组别、计划/实际阶段顺序、两台数据、峰值、提示音和共同层事件。
- [ ] 相同组别再次记录会生成另一个文件，不覆盖前一次。
- [ ] 在视频编辑软件中检查首尾时间对应；确认是否达到 ±1 帧，并记录帧率。

## M8：延迟

进入 `latency-test`。本机确认运动峰值后立即发 click，对方收到峰值事件后立即发 click。使用额外录音设备记录物理动作声音与两个 click，分别取至少 30 次测量，报告中位数与范围。峰值检测本身包含平滑和一个下降样本的确认延迟，属于端到端测量路径。

| 路径 | 次数 | 中位数 | 范围 | 设备/录音说明 |
|---|---:|---:|---|---|
| 本地动作 → 本机 click | 待测 | 待测 | 待测 | |
| 动作 → 服务器 → 对方 click | 待测 | 待测 | 待测 | |

如果轻敲桌面不能产生足够角速度，应先核对控制台峰值，再统一动作方法；不要把缺失 click 当成已测得的高延迟。按实测网络波动调整 `alignWindow`。
